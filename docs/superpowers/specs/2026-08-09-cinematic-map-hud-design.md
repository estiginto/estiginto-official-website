# 電影式真實世界地圖 HUD 設計規格

日期：2026-08-09

狀態：設計已核准，待實作計畫

目標頁面：`/map.html`

## 1. 摘要

建立一頁與現有官網內容架構分離的全螢幕互動地圖。頁面載入真實世界圖資，讓使用者搜尋全球地址、地標與興趣點（POI），搜尋結果優先偏向台灣與目前地圖視野。

視覺採電影情報中心的深黑、青藍 HUD 語言，並提供兩種可即時切換的地圖模式：

- 2D 戰術情報圖：保持俯視與高可讀性。
- 3D 城市指揮圖：使用傾斜、旋轉、地形與立體建築營造鏡頭感。

兩個模式共用同一份搜尋、目標及地圖狀態。功能明確排除導航與路線規劃；動畫只服務搜尋、鏡頭移動與目標鎖定。

## 2. 目標與非目標

### 目標

- 提供可拖曳、縮放及點選的真實互動地圖，而非靜態背景或預錄動畫。
- 搜尋現成的真實地址、地標與 POI，不要求使用者自行建立標記。
- 以台灣為搜尋優先範圍，同時保留全球搜尋與瀏覽能力。
- 支援 2D 與 3D 即時切換，切換時保留目前目標與視野。
- 使用掃描、資料解碼、鏡頭飛行及鎖定環等動畫建立電影感。
- 在桌機及手機提供完整、可理解且可操作的核心體驗。

### 非目標

- 不規劃、顯示或動畫化任何 A 到 B 的導航路線。
- 不要求定位權限，也不以使用者目前位置作為必要條件。
- 不提供登入、收藏、歷史紀錄或雲端資料儲存。
- 不提供使用者上傳地圖或自行建立地點。
- 不在本次範圍內修改現有首頁內容或主要導覽。
- 不複製或直接使用參考電影畫面及第三方 HUD 圖片。

## 3. 已核准的視覺方向

### 色彩與材質

- 主背景：接近黑色的冷調深藍。
- 主要 HUD：青藍與淺青白。
- 目標鎖定及重要狀態：小面積琥珀橘。
- 地圖底圖降低飽和度與亮度，讓道路、標籤與建築仍可辨識，但不與 HUD 爭奪注意力。
- 使用細線、切角、微量透明面板、掃描線及局部光暈；避免厚重卡片、過度霓虹及純裝飾假數據。

### 字體

- HUD、座標、狀態及控制：等寬字體。
- 地點名稱及主要介面文字：既有網站可用的無襯線中文字體。
- 所有 UI 字級需明確定義，不使用瀏覽器預設控制字級。

### 資料真實性

HUD 只顯示目前狀態或圖資實際提供的內容，例如地點名稱、類型、地址、經緯度、縮放層級、地圖模式及資料來源。不得以假流量、假天氣、假危險值或無意義亂碼填充畫面。

## 4. 頁面版面

頁面為全視窗地圖畫布，HUD 疊加於地圖之上。

### 頂部系統列

- 左側：ESTIGINTO 品牌與地圖系統名稱。
- 中央：`2D 戰術`／`3D 城市`模式切換。
- 右側：地圖載入及搜尋服務狀態。

### 搜尋命令列

- 位於頂部系統列下方中央。
- 支援中文、英文、地址、地標及 POI 名稱。
- 顯示載入中、結果數、無結果及錯誤狀態。
- 支援鍵盤上下選取、Enter 鎖定及 Escape 關閉結果。

### 左側搜尋結果列

- 搜尋前保持收合或低存在感。
- 搜尋後顯示候選地點名稱、類型及簡短位置描述。
- 鍵盤焦點、滑鼠懸停與已選狀態需清楚區分。

### 中央地圖與鎖定區

- 地圖保持可拖曳、滾輪縮放、雙指縮放及旋轉。
- 搜尋選定地點後，鏡頭移動到目標並顯示程式原生的鎖定環、十字座標與脈衝。
- 不繪製路徑線。

### 右側目標資料列

- 顯示已選地點的名稱、類型、地址、經緯度與資料來源。
- 圖資缺少的欄位直接省略，不以假資料補齊。
- 使用者關閉選取時，面板回到待命狀態。

### 底部狀態列

- 顯示目前縮放層級、中心座標、地圖模式及圖資署名。
- 保留 MapLibre、MapTiler 與 OpenStreetMap 等必要 attribution。

## 5. 核心互動流程

### 初始進場

1. 頁面以台灣全景作為預設視野。
2. 地圖載入後，HUD 以短暫通電與掃描動畫進場。
3. 地圖一旦可操作，即停止任何會阻礙拖曳或縮放的進場遮罩。

### 搜尋

1. 使用者輸入至少兩個字元。
2. 約 300 毫秒防抖後送出 MapTiler 搜尋請求。
3. 請求使用目前地圖中心作 proximity bias；初始狀態自然優先台灣，但不限制全球結果。
4. 請求明確包含地址、地名與 `poi` 類型，確保店家、設施及地標能進入候選結果。
5. 搜尋期間顯示全圖掃描線與解碼狀態。
6. 收到資料後列出候選結果，並保持使用者的輸入焦點與鍵盤操作能力。

### 選取與鎖定

1. 使用者選擇候選結果。
2. 介面進入 `focusing` 狀態，搜尋結果保持可見但降低注意力。
3. 2D 模式以俯視鏡頭推近；3D 模式增加 pitch 與有限度 bearing 變化。
4. 鏡頭抵達後進入 `locked` 狀態，展開鎖定環並顯示目標資料。
5. 使用者仍可拖曳、縮放、選擇另一個結果或切換模式。

### 2D／3D 切換

- 切換時保留搜尋文字、候選結果、已選地點、中心點及合理的等效縮放。
- 2D 將 pitch 與 bearing 動畫回到俯視基準。
- 3D 啟用地形及建築 extrusion，並將鏡頭動畫到核准的傾斜角度。
- 切換不重新呼叫地點搜尋，也不清空目標。

## 6. 動畫規格

- HUD 通電：一次性、短促，不阻塞地圖互動。
- 搜尋掃描：僅在請求進行時循環；請求完成或失敗即停止。
- 候選結果：短距離 stagger 顯示，避免逐項長時間延遲。
- 鏡頭移動：使用 MapLibre 原生相機動畫；2D 時間較短，3D 稍長但不得拖慢連續搜尋。
- 目標鎖定：由 CSS／SVG HUD 疊層呈現，包含環形展開、十字線及一次脈衝。
- 資料解碼：使用簡短 reveal，不以隨機字串長時間閃爍。
- `prefers-reduced-motion: reduce` 時取消掃描循環、旋轉及 stagger，鏡頭改為短時間或立即定位。

## 7. 技術架構

### 頁面隔離

- 新增獨立 Vite HTML 入口 `map.html`。
- 新增地圖專用 React 入口與樣式，不把功能加入既有 `src/App.jsx`。
- 在 `vite.config.js` 加入 `map` build entry。
- 僅在明確要求時才把 `/map.html` 加入現有網站導覽。

### 模組邊界

- `MapExperience`：組合頁面與共用狀態。
- `WorldMap`：建立及清理 MapLibre 實例、同步 camera、模式與目標。
- `SearchCommand`：輸入、防抖、鍵盤選取及請求狀態。
- `SearchResults`：候選結果與作用中項目。
- `TargetProfile`：呈現可用的真實地點資料。
- `HudChrome`：頂部、底部與裝飾層，且不得攔截地圖手勢。
- `usePlaceSearch`：封裝 MapTiler 請求、取消過期請求、正規化資料與錯誤。
- `mapMode` helpers：集中管理 2D／3D 相機及圖層差異。

### 狀態模型

核心狀態為：

- `mode`: `2d | 3d`
- `searchStatus`: `idle | searching | success | empty | error`
- `focusStatus`: `idle | focusing | locked`
- `query`
- `results`
- `selectedPlace`
- `camera`

搜尋狀態與鏡頭狀態分離，避免快速連續搜尋或模式切換造成相互覆蓋。

## 8. 圖資與憑證

- MapLibre GL JS 負責瀏覽器端地圖渲染、圖層、2D／3D 與相機動畫。
- MapTiler 提供地圖樣式、圖磚及 Search & Geocoding API。
- 瀏覽器端使用 `VITE_MAPTILER_KEY`。
- 該 Key 必須在 MapTiler 後台限制允許的正式網域及本機開發來源。
- 不把私密伺服器金鑰放入前端；前端公開 Key 仍需透過網域限制與用量監控降低濫用風險。
- 搜尋請求需可取消；新查詢開始後，不得讓舊回應覆蓋新結果。

## 9. 響應式設計

### 桌機

- 同時顯示左側搜尋結果與右側目標資料。
- 搜尋列保持在地圖視線中心上方，不遮住主要鎖定點。

### 平板與手機

- 左右面板改為底部抽屜，搜尋結果與目標資料使用互斥或分頁狀態。
- 頂部保留搜尋及 2D／3D 切換；品牌及非必要狀態縮減。
- 手勢操作區不得被純裝飾 HUD 攔截。
- 觸控目標至少符合一般可操作尺寸，並避免面板完全遮住地圖目標。

## 10. 無障礙與輸入方式

- 所有控制皆可鍵盤操作，具備可見焦點狀態及可理解標籤。
- 搜尋結果使用適當 combobox／listbox 語意或同等可存取模式。
- 搜尋狀態、結果數、錯誤及目標鎖定透過低干擾 live region 通知。
- 不只依靠顏色表示作用中、錯誤或鎖定狀態。
- 尊重 `prefers-reduced-motion`。
- 地圖畫布提供文字替代說明，目標資料仍能由輔助科技讀取。

## 11. 錯誤與降級處理

- 缺少 API Key：顯示明確的設定錯誤，不載入空白地圖。
- 地圖樣式或圖磚失敗：HUD 顯示圖資離線狀態並提供重試。
- 搜尋無結果：保留使用者輸入及目前地圖，不移動鏡頭。
- 搜尋網路錯誤：顯示可重試訊息，不清除上一個成功目標。
- 快速輸入：取消前一個搜尋請求，避免結果跳回舊查詢。
- WebGL 不可用：顯示易懂的瀏覽器支援提示，而不是永久載入動畫。
- 3D 圖層不可用：保留 2D 地圖及搜尋，並把 3D 控制標示為不可用。

## 12. 測試策略

### 自動化檢查

- 建置測試確認 `map.html`、地圖入口及必要資產進入 `dist`。
- 單元測試涵蓋搜尋防抖、過期請求取消、結果正規化及狀態轉移。
- 契約測試確認頁面不包含導航、路線 API 或路徑圖層。
- 瀏覽器測試以可控的搜尋回應驗證成功、無結果、錯誤及連續查詢。

### 瀏覽器 QA

- 桌機與手機檢查拖曳、縮放、搜尋、鍵盤選取、鏡頭鎖定及面板收合。
- 驗證 2D／3D 切換保留 query、results、selectedPlace 與相機中心。
- 驗證快速切換模式或快速選擇結果不會留下過期動畫及圖層。
- 驗證 reduced motion 下沒有持續掃描、旋轉或長距離飛行。
- 驗證圖資署名始終可見。
- 驗證 WebGL 或網路失敗時能進入可理解的降級畫面。

## 13. 驗收條件

- `/map.html` 可獨立開啟，且不依賴進入官網首頁後的狀態。
- 真實地圖可拖曳及縮放，初始視野位於台灣。
- 使用者可搜尋台灣及全球的真實地址、地標與 POI。
- 選擇結果會產生掃描、鏡頭移動、鎖定及資料顯示動畫。
- 2D 與 3D 均可使用，切換後仍保留同一搜尋目標與合理相機位置。
- 畫面不存在導航路線、導航步驟或定位權限要求。
- 桌機與手機均可完成搜尋及選取核心流程。
- 鍵盤、錯誤狀態、reduced motion 及必要 attribution 均通過驗證。
- 視覺實作需以核准的深黑青藍 HUD 為準，並在最終交付前與正式概念圖及瀏覽器截圖進行逐項比對。

## 14. 實作前置條件

- 準備可用且設定網域限制的 MapTiler 瀏覽器 API Key。
- 在正式編碼前，依本規格產生完整桌機主畫面及手機狀態的高解析視覺概念，確認後視為實作基準。
- 實作計畫需把頁面入口、地圖核心、搜尋、HUD／動畫、響應式及驗證拆成可獨立檢查的小步驟。
